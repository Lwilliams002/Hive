# Hive — Milestone 4: Ads (AdMob placements, frequency rules, consent) — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking. Tasks 1–5 are built, tested and committed in the Linux container (`/home/user/hive` at `130e8d2`, Swift 6.1.3, `swift test`); Tasks 6–10 write app-target Swift that only a Mac can compile; Task 11 is the Mac verification. Read `docs/superpowers/plans/2026-10-24-m4-seam-report.md` (code facts; its line numbers are exact until Task 2 reorders `World.swift`) and `docs/superpowers/plans/2026-10-24-m4-rulings.md` (the 30 design rulings) before any task; this plan follows the rulings and never re-decides them.

**Goal:** Revive, double coins, a premium fourth card and between-level interstitials, all behind Google test ad IDs, with every rule that can be stated without the SDK (downed/revive semantics, the premium side stream, bonus idempotency, the 3/3/90 frequency rule, the consent flag) living in `HiveCore` and pinned by Linux tests — while World's main RNG stream and the 14 baseline probe lines stay byte-identical.

**Architecture:** `World` is split first (refactor-only, guarded by two golden runs, a same-seed pin and the probe baselines) into `World.swift` (state, tick skeleton, the single kill and pick-open choke points) and `World+Mechanics.swift` (escorts, bees, splash). Then three additive core changes: a `.downed` phase with `revive()`/`abandonRevive()` gated by an injected `reviveAllowed`; a `premiumRNG` side stream (seed XOR constant) that rolls `premiumOffer` in the single pick-open path without touching `rng`; and `GameState` counters + `AdRules` (pure, `now` injected) + `awardBonus`. The app gains `AdProviding` (`AdMobProvider` on GMA v12 / UMP v3 behind `#if canImport`, `NoAdsProvider` fake with a DEBUG grant/cancel mode) owned by `AppFlow`, one `awaitingAd` flag in `GameScene` that keeps the current overlay alive while an ad owns the screen, a `ReviveOverlay`, a DOUBLE COINS button outside `EndOverlay`'s single-shot `actions`, a fourth card row, and interstitials decided at the end-overlay taps. World never knows about ads; scenes never touch the SDK.

**Tech Stack:** Swift 5 mode (`swiftLanguageVersions: [.v5]`, `SWIFT_VERSION 5.0`), SpriteKit/UIKit, XcodeGen, XCTest; new remote SPM packages GoogleMobileAds **v12** and GoogleUserMessagingPlatform **v3** (app target only; `HiveCore` stays Foundation-only). Swift 6.1.3 toolchain in the container for `HiveCore`; Xcode 26.2 + an iOS 16+ iPhone SE (3rd generation) simulator (375×667 pt) on the Mac for the app.

**Spec:** `docs/superpowers/specs/2026-10-22-hive-defense-design.md` §4 (anti-goals: pushy ads, pay-to-win), §5.1 step 6, §6 (placement table, test IDs, ATT once after the first level, preload + hidden-when-not-loaded, no banner, not child-directed + UMP), §7 (`AdManager`; unit tests for ad frequency rules), §8 milestone 4. Carried items: the six M4 seams in `2026-10-22-m3-deferred-and-rulings.md:60-66`.
